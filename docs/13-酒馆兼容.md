## 2. 世界书条目 → 设定条目

| 酒馆字段 | 含义 | IF 映射 |
|---|---|---|
| `key` | 主关键词 | `keys` |
| `keysecondary` | 次要关键词 | `secondary_keys` |
| `selectiveLogic` | 0 AND ANY / 1 NOT ALL / 2 NOT ANY / 3 AND ALL【待核实编号】 | `logic` |
| `constant` | 常驻 | `constant` |
| `disable` | 停用 | `status` |
| `comment` | 条目名称或备注 | `title` |
| `content` | 内容 | `content`；其中的承重断言另外抽取为事实 |
| `order` | 插入顺序 | `order` |
| `position` | 插入位置：角色定义前后、示例前后、作者注释上下、@深度【待核实完整取值】 | `section`：角色定义前后 → world / character；@深度 → scene；其余 → world |
| `depth`、`role` | @深度插入时的深度与角色 | IF 没有聊天深度的概念，统一映射为 scene 段 |
| `probability`、`useProbability` | 触发概率 | 用命运骰子实现 |
| `group`、`groupWeight`、`groupOverride` | 包含组：同组只激活一个 | 同组按权重，用命运骰子选出一个 |
| `excludeRecursion`、`preventRecursion`、`delayUntilRecursion` | 递归控制 | 保留原语义 |
| `scanDepth`、`caseSensitive`、`matchWholeWords` | 扫描深度与匹配方式 | 扫描最近 N 个节拍；匹配选项保留 |
| `sticky`、`cooldown`、`delay` | 定时效果（按消息数计） | 按场景数计 |
| `characterFilter` | 只对指定角色生效 | 仅当指定主体在场时激活 |
| `vectorized` | 向量检索激活 | 【后续】 |
| `automationId` 等 | 自动化扩展 | 忽略 |

## 3. 角色卡 → 世界

### 3.1 格式【待核实】

- V2：`{ spec: "chara_card_v2", spec_version: "2.0", data: {...} }`。PNG 中存放在名为 `chara` 的文本块里（base64 编码的 JSON）。
- V3：`spec: "chara_card_v3"`，PNG 中存放在 `ccv3` 文本块里。新增 `assets`、`nickname`、`creator_notes_multilingual`、`source`、`group_only_greetings`、`creation_date`、`modification_date` 等字段；世界书条目支持 `@@depth` 这类装饰器。
- `extensions`：应用私有数据。规范要求导入时保留，不得丢弃。

### 3.2 字段映射

| 角色卡字段 | IF 映射 |
|---|---|
| `name` | 主体名 |
| `description`、`personality` | `Subject.profile`；稳定的特质抽取为 trait 命题 |
| `scenario` | 初始局面：事实 + 候选故事线 |
| `first_mes` | 开场场景：改写为第三人称叙事，去掉对 `{{user}}` 的第二人称 |
| `alternate_greetings` | 多个开场 = 多条初始世界线（开局选择） |
| `mes_example` | `Subject.voice`：台词风格样例 |
| `system_prompt`、`post_history_instructions` | 只把其中与文风相关的部分导入为 style 条目，并由用户确认。很多内容是聊天扮演专用的指令，不适用于 IF |
| `character_book` | 设定条目；其中的承重断言抽取为事实 |
| `creator_notes`、`tags`、`creator`、`character_version` | 元数据 |
| `extensions` | 原样保存；导出时 IF 的数据放在 `extensions.if` 下【后续】 |

- 宏：`{{char}}` 替换为角色名；`{{user}}` 的处理见 [10 §7.1](10-世界创建与导入.md)。
- 群聊卡：每张卡对应一个主体，场景与世界书合并，冲突交给 Jev 检查。

## 4. 社区变量卡【待核实】

根据社区资料，常见的变量系统（例如 MagVarUpdate，也就是 MVU，配合酒馆助手和提示词模板插件使用）大致是这样工作的：

- 初始变量写在特定的世界书条目里，例如名称中带 `[InitVar]` 的条目。
- LLM 在回复中输出更新命令，例如在 `<UpdateVariable>` 块里写 `_.set('路径', 旧值, 新值);//原因`，由脚本解析后写入聊天变量（例如 `stat_data`）。
- 世界书条目可以用 EJS 模板按变量值条件化，例如 `<% if (getvar('…') > 50) { %>`。

IF 中的对应关系：

| 变量卡 | IF |
|---|---|
| 初始变量 | 命题 + 初始事实（数值 → scalar，文本 → text 或 enum） |
| 更新规则说明（通常写在世界书条目里） | 由 LLM 转成机制或触发器的候选，在世界卡中由用户确认 |
| 条件化条目 | 设定条目的 `when` 条件（[08 §5](08-视图与世界书.md)） |
| 状态栏 | IF 的右侧面板本来就有，按玩家视图显示 |

根本区别在于：**IF 不需要 LLM 输出更新命令。** 状态变化来自候选、Jev 判定和命运骰子，这正是 IF 与变量卡的分水岭。

卡中的 JS、EJS、正则等脚本一律不执行，只作为文本参考。

## 5. 预设与正则【后续】

- 预设中与文风相关的段落可以导入为 style 条目；越狱类指令不导入。
- 正则脚本可以作为"显示正则"，只在正文渲染时做格式处理，不影响状态。
