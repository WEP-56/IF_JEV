# 13 酒馆兼容

> 本文的字段与语义，根据 SillyTavern 公开文档、角色卡 V2/V3 规范和社区资料整理。
> **2026-09-26 已联网逐项核实**（见 §0），§2 / §3.1 中标【待核实】的条目已按核实结果更新为【已核实】；§6 只保留仍未核实的部分。

## 0. 已核实的官方资料

- SillyTavern 文档站：[Character Design](https://docs.sillytavern.app/usage/core-concepts/characterdesign/) 和 [World Info](https://docs.sillytavern.app/usage/core-concepts/worldinfo/)。
- 角色设计页确认：角色名是唯一必填字段；名称、描述、性格、场景属于每次生成都会带上的永久字段；首条消息只在会话开始发送；示例消息会随上下文策略逐渐被挤出或按设置保留。
- World Info 页确认：条目通过关键词动态激活；支持主关键词、次级关键词及 AND ANY / AND ALL / NOT ANY / NOT ALL；常驻条目、插入顺序和插入位置；概率过滤；包含组与权重 / 优先级；递归激活；角色过滤；扫描深度和 token budget。World Info 是上下文注入机制，不保证模型一定在输出中使用内容。
- 以上是产品行为依据；具体导入字段名仍以真实 V2/V3 JSON、PNG 内嵌 JSON 和 World Info JSON fixture 为准。

### 0.1 两套方言必须区分

核实中的一个关键事实：**「卡片内 `character_book`」与「酒馆运行时世界书导出」用的是两套字段名**，导入器必须同时兼容。已实测确认：

| 语义 | CCv3 规范（`character_book` / `lorebook_v3`） | 酒馆运行时导出 |
|---|---|---|
| 主关键词 | `keys`（数组，必填） | `key`（数组或逗号分隔字符串） |
| 次级关键词 | `secondary_keys` | `keysecondary` |
| 插入顺序 | `insertion_order`（数字，越小越早） | `order` |
| 启用 / 停用 | `enabled`（布尔） | `disable`（布尔，语义相反） |
| 位置 | `position: "before_char" \| "after_char"` | `position: 0–6`（数字） |
| 逻辑 | `selective` + `secondary_keys` | `selectiveLogic: 0–3` |
| 正则键 | `use_regex`（V3 必填） | 由 `key` 内 `/pattern/` 写法表达 |
| 条目 id | `id` | `uid` |

`crates/if-app/src/importer/lorebook.rs` 按此表做方言判定与归一化。

## 2. 世界书条目 → 设定条目

| 酒馆字段 | 含义 | IF 映射 |
|---|---|---|
| `key` | 主关键词 | `keys` |
| `keysecondary` | 次要关键词 | `secondary_keys` |
| `selectiveLogic` | 0 AND ANY / 1 NOT ALL / 2 NOT ANY / 3 AND ALL【已核实编号】 | `logic` |
| `constant` | 常驻 | `constant` |
| `disable` | 停用 | `status` |
| `comment` | 条目名称或备注 | `title` |
| `content` | 内容 | `content`；其中的承重断言另外抽取为事实 |
| `order` | 插入顺序 | `order` |
| `position` | 插入位置。运行时取值：0 主提示前 / 1 主提示后 / 2 作者注释顶 / 3 作者注释底 / 4 @深度 / 5 示例前 / 6 示例后【已核实】 | `section`：0、1 → character；4 → scene；其余（2、3、5、6）→ world |
| `depth`、`role` | @深度插入时的深度与角色 | IF 没有聊天深度的概念，统一映射为 scene 段 |
| `probability`、`useProbability` | 触发概率 | 用命运骰子实现 |
| `group`、`groupWeight`、`groupOverride` | 包含组：同组只激活一个 | 同组按权重，用命运骰子选出一个 |
| `excludeRecursion`、`preventRecursion`、`delayUntilRecursion` | 递归控制 | 保留原语义 |
| `scanDepth`、`caseSensitive`、`matchWholeWords` | 扫描深度与匹配方式 | 扫描最近 N 个节拍；匹配选项保留 |
| `sticky`、`cooldown`、`delay` | 定时效果（按消息数计）【已核实单位】 | 按场景数计 |
| `characterFilter` | 只对指定角色生效 | 仅当指定主体在场时激活 |
| `vectorized` | 向量检索激活 | 【后续】 |
| `automationId` 等 | 自动化扩展 | 忽略 |

## 3. 角色卡 → 世界

### 3.1 格式【已核实】

- V2：`{ spec: "chara_card_v2", spec_version: "2.0", data: {...} }`。PNG 中存放在名为 `chara` 的 **`tEXt` 块**里，块内是 JSON 字符串经 UTF-8 → base64 编码【已核实】。
- V3：`spec: "chara_card_v3"`，PNG 中存放在 **`ccv3`** 文本块里。**同时存在 `chara` 与 `ccv3` 时优先 `ccv3`**【已核实】。新增字段：`assets`、`nickname`、`creator_notes_multilingual`、`source`、`group_only_greetings`、`creation_date`、`modification_date`；其中 `group_only_greetings` 在 `data` 中**必须存在**（可为空数组）。`character_book` 在 V3 变为可选。世界书条目支持 `@@depth` 这类装饰器（以 `@@` 开头，回退装饰器用 `@@@`）。
- 独立世界书导出格式为 `{ spec: "lorebook_v3", data: Lorebook }`【已核实】。
- 角色卡条目 `position` 只允许 `before_char` / `after_char`；深度插入由装饰器 `@@depth` 表达，不是 `position` 取值【已核实】。导入器同时兼容编辑器写出的 `before_an` / `at_depth` 等扩展值。
- V3 另引入 CHARX（zip，根目录 `card.json`，资产用 `embeded://` URI）；v1 不导入 CHARX。
- `extensions`：应用私有数据。规范要求导入时保留，不得丢弃。
- 实现位置：`crates/if-app/src/importer/`（`card.rs` 角色卡、`lorebook.rs` 条目、`png.rs` PNG 文本块、`model.rs` DTO）。

| 角色卡字段 | IF 映射 |

## 4. 社区变量卡【待核实】

根据社区资料，常见的变量系统（例如 MagVarUpdate，也就是 MVU，配合酒馆助手和提示词模板插件使用）大致是这样工作的：

- 初始变量写在特定的世界书条目里，例如名称中带 `[InitVar]` 的条目。
- LLM 在回复中输出更新命令，例如在 `<UpdateVariable>` 块里写 `_.set('路径', 旧值, 新值);//原因`，由脚本解析后写入聊天变量（例如 `stat_data`）。
- 世界书条目可以用 EJS 模板按变量值条件化，例如 `<% if (getvar('…') > 50) { %>`。

IF 中的对应关系：

| 变量卡 | IF |
|---|---|
| 初始变量 | 命题 + 初始事实（数值 → scalar，文本 → text 或 enum） |
| 更新规则说明（通常写在世界书条目里） | 由 LLM 转成机制或触发器的候选，在世界卡中由用户确认 |
| 条件化条目 | 设定条目的 `when` 条件（[08 §5](08-视图与世界书.md)） |
| 状态栏 | IF 的右侧面板本来就有，按玩家视图显示 |

根本区别在于：**IF 不需要 LLM 输出更新命令。** 状态变化来自候选、Jev 判定和命运骰子，这正是 IF 与变量卡的分水岭。

卡中的 JS、EJS、正则等脚本一律不执行，只作为文本参考。

## 5. 预设与正则【后续】

- 预设中与文风相关的段落可以导入为 style 条目；越狱类指令不导入。
- 正则脚本可以作为"显示正则"，只在正文渲染时做格式处理，不影响状态。

## 6. 核实状态

### 6.1 已核实（2026-09-26）

1. 世界书导出 JSON 的字段名：两套方言已区分（§0.1 表）；`position` 与 `selectiveLogic` 的取值编号已确认（§2）。
2. `sticky`、`cooldown`、`delay` 按**消息数**计；sticky 保持激活 N 条消息、cooldown 阻止重新激活 N 条消息、delay 延后 N 条消息才激活。
3. 角色卡 V3 字段、装饰器清单与 PNG 文本块名称（`chara` / `ccv3`，`tEXt` 块）已确认（§3.1）。
4. 两张真实公开 V2 卡已在本地通过导入回归（`crates/if-app/tests/fixtures/`）。

### 6.2 仍未核实

4. MVU 初始化条目的命名方式（如 `[InitVar]`）、更新命令语法，以及变量的实际存储位置——**未核实**，v1 不做变量卡导入。
5. 提示词模板插件（EJS）中可用的函数——**未核实**，v1 不导入预设 / 正则。

### 6.3 仍需真实文件覆盖

以下由合成 fixture 覆盖了解析逻辑，但**不等于真实卡兼容性证明**，需要用户提供的真实文件补测：

- 真实 PNG 角色卡（`chara` / `ccv3` 文本块）。
- 含 V3 扩展字段（`assets` / `group_only_greetings` / 装饰器）的真实卡。
- 独立 `lorebook_v3` 导出的真实世界书。
- 真实酒馆运行时导出的 World Info JSON（`uid` / `key` / `selectiveLogic` / 数字 `position`）。
