# 01 IF 规则

本文定义三件事：用户能做什么；IF 如何解析、锁定、处理冲突；观测返回什么。

## 1. 用户动作

| 动作 | 作用 | 改变世界 | 写入日志 |
|---|---|---|---|
| **IF** | 注入一条必须成立的新条件 | 是 | `if_injected` 以及它锁定的事实 |
| **观测** | 获取某个主体、命题或故事线的有限信息 | 否 | `user_observed`（只影响玩家认知） |
| **继续** | 不注入 IF，让世界自行推进一个场景 | 由世界决定 | 该回合的全部事件 |

分支、回到此处、重写、重掷、回滚这些**世界线操作**，操作的是时间线而不是世界内部，见 [03 §6](03-事件与世界线.md)。

用户**不能**：指定角色下一步做什么，决定谁如何得知，决定后果，选择聚焦哪条线，宣布冲突结束，指定视角和节奏，推进或跳过时间。

## 2. IF 的定义

IF 是一条**权威的反事实断言**：

- **权威**：核心命题必须成立。
- **反事实**：它可以违反当前趋势、角色意愿或导演计划。
- **断言**：它描述世界的状态，而不是下达指令。

## 3. 时态规则

> IF 只能断言**现在或过去**为真的内容；未来只能由世界推演。

| 输入 | 判定 | 说明 |
|---|---|---|
| IF 林夏爱上了顾言 | ✓ | 现在的状态 |
| IF 林夏决定表白 | ✓ | 现在的意图；能否表白、结果如何由世界推演 |
| IF 所有人从此无法说谎 | ✓ | 从现在起生效的规则 |
| IF 十年内所有人不会衰老 | ✓ | 从现在起生效、带期限的规则 |
| IF 本季的暴雨会持续三十天 | ✓ | 同上，归为规则型 |
| IF 王宫刚刚起火了 | ✓ | 刚发生的事件 |
| IF 沈知遥已经把数据传到了网上 | ✓ | 已发生的事件；她为何这么做、后续反应由世界推演 |
| IF 这场战争其实早已结束 | ✓ | 过去的真相 |
| IF 王国从未存在过 | ✓ | 改写已展示的过去（回溯型） |
| 让林夏表白 | ✗ | 未来的行动 |
| 让反派失败 | ✗ | 未来的结局 |
| 时间快进到第 6 天 | ✗ | 叙事指令 |
| 让沈知遥在夜班时发现数据异常 | ✗ | 指定了"谁如何得知"，这由世界决定 |

两点说明：

- **带期限的规则不是未来事件。** 规则描述的是从现在起世界如何运作，而不是断言某件事一定会在某个时刻发生。
- **允许断言角色刚做过某事**（事件型）。它和"指定角色下一步行动"的区别在于：前者是既成事实，角色的动机、自我认知和后续反应仍由世界推演。如果这件事明显不符合人物，世界需要给出解释，比如隐藏动机；也可以按"异常"处理，即角色自己也说不清为什么这么做。

**未来锚点**【后续】：断言某个未来事件必然发生，世界必须收束到它。可以作为挑战模式里代价很高的特殊 IF，第一版不支持。

## 4. 导演指令的识别与改写

1. Jev 判断输入是否包含导演指令（`q.input.is_directive`）。
2. 如果包含，LLM 给出 1–3 条 IF 形式的改写建议，再由 Jev 检查改写是否保留原意、且不再是指令（`q.input.rewrite_preserves`）。用户可以选择其中一条、自行修改或取消。原输入不直接进入解析。
3. 如果不包含，直接进入解析。

| 原输入 | 改写建议 | 类型 |
|---|---|---|
| 时间快进到第 6 天，让沈知遥发现水库数据异常 | IF 上游水库的出库数据一直被人为篡改 | 真相型 |
| 让周望川说出他早就知道的事 | IF 周望川早就知道数据被篡改 | 认知型 |
| 让反派失败 | IF 反派的计划从一开始就有一个致命漏洞 | 真相型 |
| 让顾言回应林夏的感情 | IF 顾言其实也一直喜欢林夏 | 状态型 |

改写建议要明确提示用户：**改写后结果不再有保证。** 改写只是创造了让结果可能发生的条件，是否发生由世界决定。

## 5. IF 的类型

| 类型 | 断言对象 | 例子 | 锁定什么 | 默认锁定 |
|---|---|---|---|---|
| 状态型 | 主体此刻的状态、关系、意图 | IF 林夏爱上顾言 | 该状态此刻成立 | L1 |
| 认知型 | 主体此刻相信什么 | IF 顾言相信林夏背叛了他 | 该信念此刻成立，事实不变 | L1 |
| 规则型 | 世界从现在起如何运作 | IF 所有人无法说谎 | 规则持续生效 | L2 |
| 事件型 | 刚发生或正在发生的事 | IF 王宫发生了一场火灾 | 事件本身发生，后果不锁定 | 事件 L3，后果 L0 |
| 真相型 | 一直为真、但未必有人知道的事 | IF 骑士一直是失踪的王储 | 永久成立；谁知道可以变化 | L3 |
| 回溯型 | 与已展示的过去矛盾的事 | IF 王国从未存在过 | 新的过去 | L3，按消化策略处理（§12） |

- **真相型与回溯型**的区别，在于是否与读者已经读到的内容矛盾。真相型补充了一个没人知道的事实；回溯型推翻了已经展示过的内容。由 Jev 判断（`q.if.contradicts_displayed`）。
- **认知型**只写入 Belief 层，是制造误会和戏剧反讽最直接的工具。

## 6. 锁定等级

| 等级 | 名称 | 谁能改变 | 回溯修复时 | 适用对象 |
|---|---|---|---|---|
| L3 | 公理 | 只有用户显式的 IF（裁定卡会提示冲突） | 永不撤销 | 真相型、回溯型的核心命题；事件型中"事件发生"这一点 |
| L2 | 锚定 | 只有用户 IF | 可以重新解释，并在裁定卡中列出 | 规则型；世界创建时确认的设定；定型角色的核心设定 |
| L1 | 惯性 | 保护期内只能被强证据改变；期满后自然演化 | 可以修复 | 状态型、认知型 |
| L0 | 自由 | 世界自然推演 | 可以修复 | 推导出来的一切 |

## 7. L1 的保护期

如果状态型或认知型 IF 在下一幕就能被抽样"自然"推翻，用户会觉得自己的 IF 被系统吃掉了。因此：

- **保护期**：注入后 3 个场景【初始值】。按场景计而不按世界时间计（已确认），因为要保护的是玩家的体验。
- **保护期内**：任何改变该状态的候选都不参与抽样，只走阈值（p ≥ 0.85【初始值】），并且必须有明确的触发事件。
- **保护期后**：按 L0 演化。和所有状态一样，改变它的候选必须说明原因。

## 8. 最小承诺与"不承诺项"

解析结果分为**核心命题**和**不承诺项**。不承诺项是人们常会默认、但这条 IF 并不保证的推论。它们要在裁定卡上列出，让用户知道哪些交给了世界。

> IF 林夏爱上顾言
> - 核心命题：林夏对顾言的感情 = 爱（浪漫）〔事实层，此刻起〕
> - 不承诺：林夏已经意识到；林夏愿意承认；林夏会表达；顾言会察觉；顾言会回应；两人的关系立即改变

## 9. 解析与裁定卡

### 9.1 预检（在裁定卡出现之前）

| 检查 | 问题 | 用途 |
|---|---|---|
| 解析是否忠实 | `q.if.parse_faithful` | 不通过时让 LLM 重新解析一次；仍不通过，在卡上标红 |
| 类型 | `q.if.type` | 与 LLM 判断的类型不一致时，在卡上提示 |
| 是否与已展示内容矛盾 | `q.if.contradicts_displayed` | 决定是否按回溯型处理 |
| 冲突检测 | `q.if.compatible_with` | 见 §10 |
| 世界线偏移 | `q.if.prior_plausibility` | 见 §15 |

### 9.2 裁定卡字段

| 字段 | 可修改 | 说明 |
|---|---|---|
| 原文 | — | |
| 类型 | ✓ | |
| 核心命题 | ✓ | 标注属于事实层还是信念层 |
| 时间锚点 | ✓ | 此刻 / 过去某时 / 一直如此 |
| 作用范围 | ✓ | 个体 / 群体 / 地域 / 全局 |
| 锁定等级与保护期 | ✓ | |
| 规则边界 | ✓ | 仅规则型，见 §11 |
| 消化策略 | ✓（必选） | 仅回溯型，见 §12 |
| 冲突提示 | — | 见 §10 |
| 不承诺项 | — | 见 §8 |
| 世界线偏移 | — | 仅展示 |

操作：**确认 / 修改 / 取消**。

自动确认（已确认）：默认关闭，用户可以开启"无冲突且解析高度可信时自动确认"。理由是，用户的最高权限不是决定后果，而是确保系统没有曲解他要注入的事实；解析正是用户权威落地的那一步。

## 10. 冲突与优先级

### 10.1 优先级（高 → 低）

1. 当前 IF 的核心命题（用户权威）
2. L3 公理
3. L2 锚定
4. 已展示正文确立的事实
5. L1 惯性
6. L0 推导事实

这个顺序用于 IF 注入时的冲突处理和回溯修复。平时的正文不会与 L1 以上的事实冲突，因为展示前的检查会拦住它。

### 10.2 处理流程

1. **检测**：对作用范围内 L1 及以上的事实和已展示事实，逐条问 `q.if.compatible_with`（两者能否同时成立）。
2. **重释**：发现冲突时，LLM 提出 1–3 个能让两者同时成立的解释，Jev 判断是否自然（`q.if.reconcile_plausible`），采用得分最高且过阈值的一个。
3. **让位**：找不到可行的重释时，优先级低的一方让位。如果让位的是已展示事实、L3 或 L2，按回溯型处理（需要选择消化策略）。
4. **提示**：
   - 冲突对象对玩家可见：在裁定卡上直接列出。
   - 冲突对象对玩家隐藏：只提示"这与一个你尚未知晓的真相冲突，将以重释（或改写）的方式处理"，不透露内容。这句提示本身就是线索，配合观测可以形成侦探式玩法。

> 隐藏真相：骑士是失踪的王储。用户 IF：骑士是农夫的儿子。
> → 重释：王储自幼被农夫收养。两者同时成立。

> 规则：所有人无法说谎。用户 IF：林夏刚刚对顾言撒了谎。
> → 可能的重释：林夏说了一句误导性的真话（前提是规则边界允许误导）。否则这条 IF 构成规则的例外，裁定卡要让用户确认：是修改规则，还是放弃这条 IF。

### 10.3 用户自己的两条 IF 冲突

已确认：先尝试重释；失败时新 IF 覆盖旧 IF，并在裁定卡上明示被覆盖的内容。

## 11. 规则型 IF 的编译

规则型 IF 在锁定时被编译成四部分，引擎能机械执行的部分尽量不依赖 Jev：

| 部分 | 执行者 | 说明 |
|---|---|---|
| 不变量 | 引擎 | 数据层面必须始终成立的条件 |
| 机制 | 引擎 | 随世界时间更新数值的公式；随机范围用命运骰子取值 |
| 触发器 | 引擎 | 条件满足时生成候选或趋势 |
| 语义约束 | Jev | 编译不了的部分，作为约束类问题加入相关检查 |

此外还有**边界解释**，由用户在裁定卡上确认。故事一定会去试探规则的边缘。

| 规则 | 编译结果 |
|---|---|
| 所有人无法说谎 | 不变量：每条 Claim 的内容必须与说话者当时的 Belief 一致。语义约束：台词不得是说话者明知为假的陈述。边界：误导性的真话是否允许【用户确认】；沉默允许 |
| 本季的暴雨会持续三十天 | 机制：第 1–30 天天气为暴雨；江水位每天上涨 0.4–1.2 m。触发器：水位 > 28.5 m 时生成"老城区内涝"候选 |
| 十年内所有人不会衰老 | 不变量：期限内与年龄相关的状态不变。语义约束：正文不得描写衰老迹象 |
| 魔法消失了 | 语义约束：不得出现成功的施法。边界：魔法物品是否一并失效【用户确认】 |

## 12. 回溯型 IF 的消化策略

| 策略 | 事实层 | 认知层 | 已展示正文 | 适合 |
|---|---|---|---|---|
| **改写** | 过去被替换，下游重新判定 | 所有人的记忆随之改变 | 标记为"旧世界残影" | 彻底换一种历史 |
| **重释** | 过去的事件保留，补充新事实改变其意义 | 角色逐步发现新的意义 | 保留，并加注新含义 | 反转、真相揭露 |
| **异常** | 同改写 | 指定角色保留旧记忆（Belief ≠ Reality） | 标记为残影 | "世界被改写了"的悬疑感 |

- 策略由用户在裁定卡上选择，模板可以预设默认值。
- v1 只支持**重释**；改写与异常【后续】，见 [15](15-v1范围.md)。
- 执行前，引擎自动为当前世界线保存一个备份分支，旧世界线完整保留（已确认默认开启）。
- 执行细节见 [03 §7](03-事件与世界线.md)。

## 13. 观测

- **目标**：主体、命题、故事线或地点。
- **返回内容**：由引擎按可见性规则选取，LLM 负责措辞，Jev 检查是否泄密（`q.observe.leaks_secret`）。可能包括：
  - 当前可见的证据
  - 某个角色的表层信念或情绪
  - 某个趋势的模糊压力（例如"暗流涌动"，不给出具体内容）
  - 某条故事线正在积累的异常
- **不会直接揭示** visibility 为 secret 的事实，只给线索（例如"他似乎在隐瞒什么"）。
- 结果写入玩家认知投影，不改变世界。
- **频率**（已确认）：沙盒模式下每个场景边界 1 次。如果不限次数，反复观测会让有限上帝视角退化成全知视角。

## 14. 干预时机

- IF 与观测都在**场景边界**提交。正文生成过程中，可以先点"停止"（场景在最后一个已展示的节拍处结束），再提交。
- **命运节点**：由 Jev 判断此刻是否处在关键转折点（`q.window.fate_node`）。沙盒模式中只作为界面提示，不限制提交。

## 15. 世界线偏移（反事实代价）

- p：Jev 对"在注入之前的世界里，核心命题自然成立的程度"的判断（`q.if.prior_plausibility`）。
- 偏移 = −ln(max(p, p_min))，其中 p_min = 0.001【初始值】。
- 沙盒模式：只展示，并累计到世界线上。挑战模式：作为预算消耗【后续】。
- 界面上称为"世界线偏移"或"现实阻力"，**不宣传为客观概率**。它只是 Jev 在一个明确定义的尺度下给出的语义自然度。

## 16. 模式

| 模式 | 状态 | 规则 |
|---|---|---|
| 沙盒 | 【v1】 | 无限 IF，无胜负，观察世界如何回应 |
| 挑战 | 【后续】 | 有限预算、目标、隐藏信息；引擎预留规则集接口 |
