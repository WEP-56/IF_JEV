# 03 事件与世界线

## 1. 事件日志是唯一真相

- 只追加，不修改，不删除。
- 当前世界 = 把当前世界线上的事件按顺序折叠得到的投影。
- IF 注入本身也是事件；它的核心命题在投影中享有 Canon 地位（L3 或 L2）。

## 2. 事件

```ts
interface Event {
  id: string;                 // "evt_0192"
  line: string;               // 首次写入时所在的世界线
  seq: number;                // 追加顺序
  world_time: WorldTime;      // 在世界中发生的时间，可以早于前一条事件
  narrative_order?: number;   // 叙述顺序，只有上屏的事件才有
  type: EventType;
  payload: Patch;             // 对投影的修改
  caused_by: string[];        // IF、事件或趋势
  depends_on: string[];       // 依据的事实与信念
  turn: string;               // 所属回合
  scene?: string;
  beat?: string;
}
```

判定与裁决不写进事件，而是记在回合记录里，事件通过 `turn` 关联。这样事件保持精简，审计信息也完整保留。

## 3. 回合记录

```ts
interface TurnRecord {
  id: string;
  line: string;
  kind: 'if' | 'continue' | 'observe' | 'background' | 'creation';
  input?: string;
  tasks: TaskRecord[];        // 每个 agent 任务的消息、工具调用与结果，见 05
  candidates: Candidate[];
  judgments: Judgment[];      // 见 07 §5
  resolutions: Resolution[];
  scene_plan?: ScenePlan;
  committed: string[];        // 本回合提交的事件 ID
  metrics: { latency_ms: number; llm_tokens: number; jev_tokens: number };
}

interface Resolution {
  target: string;             // 候选或问题的 ID
  policy: 'threshold' | 'seeded_sample' | 'weighted_select' | 'numeric';
  decision_key?: string;      // 命运骰子的键
  die?: number;               // 骰子值
  accepted: boolean | string; // 布尔值，或选中的选项
}
```

示例：

```json
{
  "candidate_id": "cand_004",
  "judgment": {
    "template": "q.perception.notices@1",
    "primitive": "noul",
    "output": { "noul": 0.58 },
    "model": "typesafe/jev-1.13-20260917"
  },
  "resolution": { "policy": "seeded_sample", "decision_key": "c_gu.notices.c_lin_abnormal@D7", "die": 0.41, "accepted": true }
}
```

`model` 写响应回显的**固定快照版本**，不是请求时的别名；判定记录的完整字段见 [07 §5](07-Jev问题库.md)。

## 4. 事件类型（v0.1）

| 类别 | 类型 |
|---|---|
| 世界 | `world_created`、`subject_created`、`subject_shaped`、`rule_added`、`rule_changed`、`lore_added`、`lore_superseded` |
| IF | `if_injected`、`if_conflict_resolved` |
| 事实 | `fact_set`、`fact_ended` |
| 认知 | `belief_set`、`claim_made` |
| 叙事 | `scene_started`、`beat_displayed`、`scene_completed`、`time_advanced` |
| 结构 | `thread_opened`、`thread_stage_changed`、`tendency_created`、`tendency_updated`、`tendency_erupted` |
| 后台 | `background_settled` |
| 玩家 | `user_observed` |
| 回溯 | `retcon_applied`、`retcon_repaired` |

`beat_displayed` 在节拍展示的那一刻立即写入。这样即使程序崩溃，日志也知道玩家看到过什么。

## 5. 投影

| 投影 | 内容 |
|---|---|
| World | 当前有效的事实、规则、主体、设定条目 |
| Belief | 每个主体（含玩家）的信念 |
| Relationship | 关系类命题的索引 |
| Thread | 故事线状态 |
| Tendency | 潜在趋势 |
| Narrative | 当前世界线已展示的节拍序列（含"旧世界残影"标记） |

- 每 200 个事件保存一次投影快照【初始值】；重建时从最近的快照开始折叠。
- 投影计算必须是确定性的：同一事件序列永远得到同一个投影。

## 6. 世界线

世界线是一个指向某个事件的"头指针"，同时记录父世界线与分叉点。

```ts
interface WorldLine {
  id: string;
  parent?: { line: string; at_seq: number };
  head_seq: number;
  label: string;
  kind: 'main' | 'branch' | 'swipe' | 'retcon_backup' | 'road_not_taken' | 'abandoned';
}
```

所有操作都只是创建或移动头指针，不删除任何事件：

| 操作 | 语义 |
|---|---|
| 分支 | 从某个节点创建新世界线，并切换过去 |
| 回到此处 | 同"分支"。建议把前端现有的"回溯"按钮改成这个名字，避免与回溯型 IF 混淆 |
| 重写 | 在同一场景起点创建 swipe 分支，**沿用同一批骰子**，只重写正文 |
| 重掷 | 同重写，但更换该场景的盐值，所有骰子重新掷 |
| 回滚 | 头指针退回到该回合之前；被退回的事件留在一条 abandoned 分支上 |
| 未选之路 | 导演没有选中的高分场景候选记为潜在分支（不生成正文），随时可以"走这条路" |

- swipe、road_not_taken、abandoned 在 IF 导图中默认折叠。
- 清理废弃分支【后续】。

## 7. 回溯型 IF 的执行

1. 保存 retcon_backup 分支（默认开启，已确认）。
2. 追加 `retcon_applied` 事件：world_time 为被改写的那个过去时刻，payload 为新的过去事实。
3. **影响分析**：沿 `depends_on` 找出所有依赖被改写事实的下游事实（传递闭包），按 world_time 排序。
4. **按消化策略修复**：
   - 改写：逐条让 Jev 判断下游事实在新历史下是否仍然成立，不成立的追加修复事件；角色的信念同步到新历史。L3 事实不参与撤销。
   - 重释：LLM 为冲突点提出补充事实，让旧事件在新历史下仍然成立；由 Jev 判断是否自然；然后追加这些补充事实。
   - 异常：事实层的处理同改写；指定角色的信念保留旧历史（Belief ≠ Reality）。
5. 已展示的节拍中与新历史矛盾的部分，在叙事投影里标记为"旧世界残影"（界面上淡化或划线显示），不删除。
6. 相关的设定条目如果过时，追加 `lore_superseded`。
7. 所有修复事件都追加在日志末尾，各自的 world_time 落在过去。

修复范围上限：最多 50 条下游事实【初始值】。超过时提示用户这条 IF 影响过大，建议改用分支。

## 8. 命运骰子

```
u = H(world_seed ‖ decision_key ‖ salt) → [0, 1)
```

- **world_seed**：世界创建时生成，写入 `world_created`。它属于世界，不属于全局设置。
- **decision_key**：跨世界线稳定的决策标识，由引擎按以下约定生成。

  | 决策 | 键的格式 | 例子 |
  |---|---|---|
  | 状态候选 | `<命题键>@<世界时间段>` | `c_gu.notices.c_lin_abnormal@D7` |
  | 互斥选择 | `<选择点键>@<世界时间段>` | `c_lin.reaction_to_feeling@D7` |
  | 场景选择 | `scene_select@<叙述序号>` | `scene_select@48` |
  | 数值机制 | `<机制 ID>@<机制步>` | `m_river_rise@D8` |
  | 设定条目概率激活 | `lore:<条目 ID>@<场景序号>` | `lore:e_12@48` |

- **salt**：默认为空；重掷时给该场景换一个盐值。
- **H**：固定的哈希算法（如 BLAKE3），取前 53 位映射到 [0, 1)。
- **Choice 抽样**：选项按选项 ID 排序后累加分布，用 u 定位落在哪个选项。
- **世界时间段的粒度**：等于世界的机制步长（已确认）。粒度越粗，两条世界线越容易共用同一颗骰子。

这样设计带来的性质：

- 两条世界线上同一个决策键用的是同一颗骰子。只有当 p 越过了 u，结果才会翻转。
- 因此可以准确展示一个 IF 改变了什么，例如：`骰子 0.55，旧世界线 p = 0.41 → 未发生；新世界线 p = 0.72 → 发生`。
- 世界线之间的偏移可以按"翻转的决策数 × 重要性"来计算。
- 重放时不重新询问 Jev，直接使用回合记录中的裁决。只有回溯修复和显式的重新评估，才会重新判定。
