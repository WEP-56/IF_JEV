# 02 世界模型

世界由下列记录构成。它们都是事件日志的投影（见 [03](03-事件与世界线.md)）：引擎从不直接修改它们，只追加事件。

```
主体 Subject
 └─ 命题 Proposition ─┬─ 事实 Fact      Reality 层：世界中为真
                      ├─ 信念 Belief    Belief 层：主体相信为真
                      └─ 声称 Claim     Claim 层：主体向别人表达了什么
规则 WorldRule · 故事线 Thread · 趋势 Tendency · 设定条目 LoreEntry · 场景 Scene / 节拍 Beat
```

下面的结构用 TypeScript 风格书写，只表达字段与含义；实现时对应 Rust 类型（serde）。

## 1. 主体 Subject

```ts
interface Subject {
  id: string;              // 稳定 ID，如 "c_lin"；名字可以改，ID 不变
  kind: 'character' | 'group' | 'faction' | 'location' | 'item' | 'concept';
  name: string;
  aliases: string[];
  profile: string;         // 自然语言设定：外貌、性格、背景
  voice?: string;          // 说话方式与台词样例（可来自角色卡的 mes_example）
  tier: 'foreground' | 'active' | 'dormant';  // 模拟分辨率，见 09
  shaped: boolean;         // 是否已定型
  created_by: EventId;
}
```

- 主体的可变状态一律用命题表达，不直接挂在 Subject 上（名字和设定文本除外）。
- 未定型的主体，设定可以被 LLM 的候选补充；定型后核心设定升为 L2，只能经 IF 修改（见 [10](10-世界创建与导入.md)）。

## 2. 命题 Proposition

命题是"可以取值的陈述"。事实、信念、声称都指向命题。

```ts
interface Proposition {
  id: string;
  key: string;             // 规范键，如 "c_lin.feeling.c_gu"
  text: string;            // 自然语言，如 "林夏对顾言的感情"
  subjects: string[];
  kind: 'state' | 'relation' | 'intention' | 'occurrence' | 'trait';
  value_type: 'bool' | 'enum' | 'scalar' | 'text';
  enum_values?: string[];
  scale?: { min: number; max: number; unit?: string };
  internal: boolean;       // 内在状态（情感、意图、信念倾向）为 true，外在状态为 false
}
```

| kind | 含义 | 例子 |
|---|---|---|
| state | 主体的状态 | 顾言的伤势；江水位 |
| relation | 两个主体之间的状态 | 顾言对林夏的信任 |
| intention | 目标、计划、决定，是角色自驱力的来源 | 林夏想阻止顾言离开 |
| occurrence | 某事件是否发生过 | 王宫起火 |
| trait | 相对稳定的特质 | 周望川的腿伤旧疾 |

### 2.1 规范键与去重

- 键的格式：`<主体ID>.<属性>[.<对象ID>]`，属性用英文 snake_case；界面显示用 `text`。
- LLM 提出新命题时，引擎先按主体和属性检索相近命题，再由 Jev 判断是否同义（`q.key.equivalent`）。同义就复用已有命题。
- 命题一经创建就不删除，只会失效。

## 3. 事实 Fact（Reality 层）

```ts
interface Fact {
  prop: string;
  value: Value;
  valid_from: WorldTime;
  valid_to?: WorldTime;          // 被后续事件结束时填写
  lock: 'L3' | 'L2' | 'L1' | 'L0';
  protected_until?: number;      // L1 保护期截止的场景序号
  visibility: 'public' | 'private' | 'secret';
  depends_on: string[];          // 推出它所依据的事实与事件，回溯修复时使用
  source: EventId;
}
```

- 同一命题在同一世界时间只有一个有效值。
- visibility 决定默认的认知传播和玩家可见性：public 表示在场者都能感知，private 表示只有相关主体知道，secret 表示被刻意隐藏。

## 4. 信念 Belief

```ts
interface Belief {
  holder: string;          // 主体 ID；"user" 表示玩家
  prop: string;
  value: Value;            // 相信的值，可以与事实不同
  belief: number;          // 0–1，相信程度
  certainty: number;       // 0–1，坚定程度：越高越难被新证据改变
  sources: EventId[];      // 亲历、被告知、推断
  updated_at: WorldTime;
}
```

没有 Belief 记录，表示该主体对此一无所知。

### 4.1 信念更新规则

| 来源 | 更新方式 |
|---|---|
| 亲历公开事件 | 在场主体直接获得信念（belief 高） |
| 细微的变化 | 发生类问题"X 是否注意到 Y"（`q.perception.notices`），掷骰决定 |
| 被告知（Claim） | 强度类问题"B 会在多大程度上相信 A"（`q.claim.credibility`），按结果更新 |
| 推断 | LLM 提出候选，Jev 判断，掷骰决定 |
| 认知型 IF | 直接写入，锁定为 L1 |

被告知时的更新公式：`belief' = certainty × belief + (1 − certainty) × level`。其中 level 是可信度等级对应的数值（见 [06 §7](06-裁决策略.md)）。

### 4.2 玩家也是认知主体

玩家的认知投影（holder = "user"）有四个来源：已展示正文确立的事实与声称；玩家自己注入的 IF；观测结果；推演卡中允许显示的变化。**有限上帝视角就是玩家认知投影。**

## 5. 声称 Claim

```ts
interface Claim {
  id: string;
  speaker: string;
  audience: string[];
  prop: string;
  claimed_value: Value;
  sincerity: 'sincere' | 'lie' | 'mislead' | 'unknown';
  world_time: WorldTime;
  source: EventId;
}
```

- sincerity 由引擎推出：把声称的值和说话者当时的信念比较，一致为 sincere，相反为 lie。字面为真但意在误导的为 mislead，这需要 Jev 判断（`q.claim.misleading`）。
- Claim 进入受众的信念更新流程，它本身永远不直接写入事实层。

## 6. 规则 WorldRule

```ts
interface WorldRule {
  id: string;
  text: string;
  lock: 'L3' | 'L2';
  source: EventId;               // IF 或世界创建
  active: { from: WorldTime; to?: WorldTime };
  scope: string[];               // 适用的主体或地域；空表示全局
  invariants: Invariant[];       // 引擎机械校验
  mechanics: Mechanic[];         // 按世界时间更新数值
  triggers: Trigger[];           // 条件满足时生成候选或趋势
  constraints: string[];         // Jev 语义约束（问题模板 ID + 参数）
  boundaries: string[];          // 边界解释（用户在裁定卡上确认过）
}

interface Mechanic {             // 例：江水位每天上涨 0.4–1.2 m
  id: string;
  target: string;                // 命题键
  per: 'step';                   // 每个机制步长执行一次
  delta: { min: number; max: number };  // 用命运骰子取值
  when?: Condition;
}

interface Trigger {              // 例：水位 > 28.5 m 时生成"老城区内涝"候选
  id: string;
  when: Condition;               // 对数值命题的比较，可以组合
  produces: { kind: 'candidate' | 'tendency'; text: string };
  once: boolean;
}
```

编译规则见 [01 §11](01-IF规则.md)。

## 7. 故事线 Thread

```ts
interface Thread {
  id: string;
  title: string;
  question: string;            // 这条线要回答的问题，如"顾言会不会离开"
  stakes: string;              // 代价与利害
  subjects: string[];
  stage: 'seeded' | 'developing' | 'escalating' | 'climax' | 'resolved' | 'abandoned';
  protected_until?: Stage;     // 到达该阶段之前不得解决
  pressure: number;            // 0–1
  last_advanced: number;       // 上次推进时的场景序号
  cadence: number;             // 期望每隔多少个场景推进一次
}
```

- 阶段转移由 Jev 判断（`q.thread.stage`）。只允许转到相邻阶段；跨阶段必须由用户 IF 触发（已确认）。
- 受保护的故事线会自动生成 forbidden_resolutions（见 [04](04-回合流程.md)）。
- 篇章与结局【后续】：所有故事线都已解决或搁置时，导演可以提出篇章收束的候选。沙盒模式没有强制结局。

## 8. 潜在趋势 Tendency

```ts
interface Tendency {
  id: string;
  text: string;                // 如"顾言开始怀疑林夏"
  target: string;              // 爆发后对应的命题或事件
  pressure: number;            // 0–1
  threshold: number;           // 爆发阈值
  contributors: EventId[];
  status: 'latent' | 'erupted' | 'dissolved';
}
```

- 来源：被掷骰否决、但概率落在观察带内的候选；规则触发器；后台结算。
- 默认对玩家隐藏，观测只返回模糊的压力（见 [01 §13](01-IF规则.md)）。
- 压力如何更新、何时爆发，见 [06 §5](06-裁决策略.md)。

## 9. 设定条目 LoreEntry（世界书）

设定条目是静态的设定文本，例如地理、历史、组织、风俗、文风说明。它们不是可变状态，而是按需检索进上下文的背景资料。激活机制沿用酒馆世界书（见 [08](08-视图与世界书.md)、[13](13-酒馆兼容.md)）。

```ts
interface LoreEntry {
  id: string;
  title: string;
  content: string;
  keys: string[];                // 触发关键词
  secondary_keys: string[];
  logic: 'and_any' | 'and_all' | 'not_any' | 'not_all';
  subjects: string[];            // 关联的主体：主体处于焦点时直接激活
  when?: Condition;              // 条件激活，引用事实
  constant: boolean;
  order: number;
  section: 'world' | 'character' | 'scene' | 'style';   // 放进提示词的哪一节
  visibility: 'public' | 'secret';
  known_by: string[];            // secret 条目：哪些主体知道
  status: 'active' | 'superseded';
  source: EventId;
}
```

设定条目与事实的分工：**凡是会被引用、会被 IF 改变、需要参与冲突检测的内容，都必须是事实；只提供氛围和背景的内容，可以留在设定条目里。** 导入世界书时，条目中的承重断言会被抽取成事实（见 [10](10-世界创建与导入.md)）。

## 10. 场景与节拍

```ts
interface ScenePlan {
  goal: string;
  pov: string;                     // 视角人物
  focus: string[];                 // 焦点主体
  time_span: string;               // 世界时间跨度
  required_beats: string[];
  stop_condition: string;
  forbidden_resolutions: string[]; // 引擎根据受保护的故事线注入，加上计划自带的
  reveal_allowed: string[];        // 本场景允许向读者揭示的事实
  proposed_changes: string[];      // 本场景要体现的预演变化
}

interface Beat {
  id: string;
  scene: string;
  index: number;
  text: string;
  plan_beat?: number;              // 对应 required_beats 中的哪一条
  judgments: string[];             // 放行检查的判定记录
  displayed_at?: Timestamp;
}
```

## 11. 状态的三个阶段

| 阶段 | 存放位置 | 进入投影 | 说明 |
|---|---|---|---|
| Proposed（预演） | 回合工作区 | 否 | 掷骰通过、用于指导写作的变化 |
| Observed（观察） | 回合工作区 | 否 | 从已展示正文中抽取、经 Jev 校对的内容 |
| Committed（提交） | 事件日志 | 是 | 回合结束时由引擎写入 |

对账规则：

1. Observed 全部提交，因为它们已经展示给玩家。
2. Proposed 中的**内在状态**（感情、意图、信念、倾向），只要没有被正文否定，可以在正文之外提交。
3. Proposed 中的**外在事件**（行动、可见的变化），必须在正文中出现过才提交；没出现的退回候选池，或转为趋势。
4. 正文与 Proposed 矛盾时，以正文为准，该 Proposed 作废。

## 12. 值与时间

- `Value = boolean | number | string`，具体含义由命题的 value_type 决定。
- **世界时间**：内部用整数表示（自世界纪元起经过的分钟数），显示格式由世界设定决定，如"第 7 天 02:17"。最小单位为分钟（已确认）。
- **叙述顺序**：递增的整数，只有上屏的事件才有。
