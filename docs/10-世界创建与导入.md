# 10 世界库与导入

本产品先管理用户准备好的世界材料，再启动游戏。第一版不以 LLM 从零生成世界为入口：用户可以导入酒馆角色卡 / 世界书，也可以自行撰写和整理世界。LLM 可以协助理解导入材料，但任何抽取或改写都先作为可审阅草案，不静默改变原始内容。

## 1. 入口

| 入口 | 说明 |
|---|---|
| 导入 | 酒馆角色卡 V2 / V3、PNG / JSON、世界书 JSON，见 §7 和 [13](13-酒馆兼容.md) |
| 手动撰写 | 在世界库中创建世界，并编辑简介、角色、世界书条目等内容 |
| 模板 | 后续提供可复制的预制世界 |

世界库资产与游戏会话是不同对象。一个世界可以有多个游戏会话；新建会话必须先选择一个可用世界。新建会话只创建会话记录和初始运行状态，不创建或复制世界。

## 2. 世界库管理

- 世界库是独立的二级页面，不属于某一条游戏会话。
- 页面提供导入、手动新建、查看、编辑、复制和删除世界；导入先进入预览 / 编辑状态，用户确认后才成为可用世界。
- 原始导入文件和字段应保留，规范化后的 IF 表示用于检索、权限过滤和上下文编译。
- 删除被会话引用的世界时，不得静默删除会话数据；应阻止删除或要求用户先处理关联。

## 3. 创建会话与世界注入

1. 用户点击“新建会话”。
2. 必须先选择一个世界；没有可用世界时，提供前往世界库导入或撰写的入口，并禁止继续。
3. 用户确认后创建属于该世界的新会话，保存世界 ID / 版本引用和会话配置。
4. host 根据当前任务编译该世界的上下文、工具和视图，再发送给 LLM；不把不适用于当前任务或视角的秘密无差别注入。
5. 进入初始场景 / 游戏回合。会话事件日志与世界库原稿分离。

## 5. 世界设置（每个世界单独保存）

| 设置 | 说明 |
|---|---|
| 世界种子 | 命运骰子的种子，创建时生成 |
| 叙事风格 | 文学叙事 / 轻小说 / 剧本体 / 白描…… |
| 叙事视角 | 默认第三人称有限视角，见 [08 §2](08-视图与世界书.md) |
| 机制步长 | 小时 / 天 / 周 / 月 |
| 导演风格 | 一组权重，见 [06 §6](06-裁决策略.md) |
| 模式 | 沙盒【v1】/ 挑战【后续】 |

这些设置在前端目前放在全局设置里，需要移到每个世界单独保存（见 [11](11-前端交互.md)）。

## 6. 角色定型

- 未定型的角色是草稿，LLM 可以通过候选补充它的设定。
- 定型之后，核心设定升为 L2，只能经 IF 修改；外貌描述成为生图时保持一致的锚点（对应 frontend-example 里的"定型后自动生成立绘"）。
- 在界面上直接修改角色时，按 P13 生成一条状态型 IF，并经过裁定卡。

## 7. 导入细节

1. **读取文件**：PNG 角色卡（读出内嵌的 JSON）、JSON 角色卡、世界书 JSON；不执行卡片脚本。
2. **映射**：优先做确定性字段映射；LLM 语义抽取只生成可审阅草案。
3. **校验**：Jev 检查抽取是否忠实（复用 `q.extract.faithful`），以及设定之间是否一致。
4. **审阅**：用户在世界库中编辑并确认映射结果。
5. **写入**：保存为世界资产；原始文件作为来源附件保留，便于日后重新导入。

字段映射见 [13](13-酒馆兼容.md)。

### 7.1 如何处理 `{{user}}`

很多角色卡以"用户扮演的角色"为中心，而 IF 的用户并不在世界之中。已确认把 `{{user}}` 转成一个由世界推演的主角：用户的人设成为主角的设定，用户自己则成为主角的"命运"。这也是一种很有辨识度的玩法：你不再扮演主角，而是改写主角的命运。
