# 10 世界创建与导入

## 1. 入口

| 入口 | 说明 |
|---|---|
| 模板 | 预制的世界，包含导演风格、规则和角色 |
| 引导创建 | 任务 T-create 与用户对话，逐步建立世界 |
| 一句话起世界 | 用户的第一条 IF 就是种子，LLM 围绕它补全一个最小的世界（对应 frontend-example 里的"给我一个起点吧"） |
| 导入 | 酒馆角色卡、世界书、变量卡，见 §7 和 [13](13-酒馆兼容.md) |

## 2. 引导创建

T-create 按以下顺序引导。每一步都给出建议值，用户可以跳过（采用默认值）：

1. 世界观与题材
2. 故事规模与时空范围
3. 主体的类别与数量
4. 文风与叙事视角
5. 故事张力与导演风格
6. 角色与群体，包括每个主要角色的目标
7. 世界规则（边说边编译成不变量、机制、触发器和语义约束）
8. 代表性的地点、物品和现象（可以作为设定条目）
9. 初始矛盾、故事线与临时事件

每一步的结果通过创建类工具写入世界草案。

## 3. 世界草案检查

提交草案之前，由 Jev 和引擎检查：

- 设定之间没有矛盾（`q.world.consistent`）。
- 主要角色的目标之间存在实质冲突（`q.world.goal_conflict`）。没有冲突的世界不会自己转起来。
- 至少有一条带代价的故事线。
- 所有规则都已编译，边界已确认。
- 叙事视角和文风已设定。

## 4. 世界卡与封存秘密

- 草案以世界卡的形式交给用户审阅，确认后写入 `world_created`。
- **封存秘密**（已确认）：LLM 在创建时追加的隐藏真相默认不在世界卡中显示，只提示"世界中还有 N 个未揭示的秘密"，用户可以选择查看。用户自己指定的内容始终可见。
- 世界卡中确认过的设定锁定为 L2。封存的秘密同样是 L2，但与用户的 IF 冲突时，按 [01 §10](01-IF规则.md) 处理。

## 5. 世界设置（每个世界单独保存）

| 设置 | 说明 |
|---|---|
| 世界种子 | 命运骰子的种子，创建时生成 |
| 叙事风格 | 文学叙事 / 轻小说 / 剧本体 / 白描…… |
| 叙事视角 | 默认第三人称有限视角，见 [08 §2](08-视图与世界书.md) |
| 机制步长 | 小时 / 天 / 周 / 月 |
| 导演风格 | 一组权重，见 [06 §6](06-裁决策略.md) |
| 模式 | 沙盒【v1】/ 挑战【后续】 |

这些设置在前端目前放在全局设置里，需要移到每个世界单独保存（见 [11](11-前端交互.md)）。

## 6. 定型

- 未定型的角色是草稿，LLM 可以通过候选补充它的设定。
- 定型之后，核心设定升为 L2，只能经 IF 修改；外貌描述成为生图时保持一致的锚点（对应 frontend-example 里的"定型后自动生成立绘"）。
- 在界面上直接修改角色时，按 P13 生成一条状态型 IF，并经过裁定卡。

## 7. 导入流程

1. **读取文件**：PNG 角色卡（读出内嵌的 JSON）、JSON 角色卡、世界书 JSON。
2. **抽取**：LLM 把内容拆成主体、事实、规则、故事线和设定条目。承重的断言变成事实，纯粹的背景留作设定条目。
3. **校验**：Jev 检查抽取是否忠实（复用 `q.extract.faithful`），以及设定之间是否一致。
4. **审阅**：生成世界卡，交给用户确认。
5. **写入**：写入 `world_created`。原始文件作为附件保存，便于日后重新导入。

字段映射见 [13](13-酒馆兼容.md)。

### 7.1 如何处理 `{{user}}`

很多角色卡以"用户扮演的角色"为中心，而 IF 的用户并不在世界之中。已确认把 `{{user}}` 转成一个由世界推演的主角：用户的人设成为主角的设定，用户自己则成为主角的"命运"。这也是一种很有辨识度的玩法：你不再扮演主角，而是改写主角的命运。
