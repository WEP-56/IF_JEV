# 08 视图与世界书

每个消费方（LLM 任务和 Jev 请求）只接收专门为它编译的视图（P9）。视图由两部分组成：**结构化状态切片**（来自投影）和**设定条目**（世界书）。

## 1. 视图类型

| 视图 | 内容 | 消费方 |
|---|---|---|
| 上帝视图 | 全部事实（含秘密）、各主体的信念摘要、规则、故事线、趋势 | Jev 的世界类、冲突类问题；T-impact、T-reconcile、T-offscreen |
| 导演视图 | 上帝视图，加上引擎的导演信号（逾期的故事线、出场统计、近期场景摘要） | Jev 的导演问题；T-scenes、T-plan |
| 角色视图（X） | X 的设定、状态、目标、信念，亲历和被告知的历史，可感知的环境，公开知识 | Jev 的行为、感知、认知越界问题；`read_pov` |
| 叙事视图 | 场景计划、在场角色的角色视图摘要（标注认知边界）、允许揭示的事实、文风、近期正文 | T-render |
| 检查视图 | 节拍文本、相关约束、相关事实、在场角色的认知边界、未批准揭示的秘密 | Jev 的节拍检查、回收检查；T-extract |
| 解析视图 | 用户输入、相关的世界切片（以玩家可见的部分为主） | Jev 的解析问题；T-parse、T-rewrite |
| 玩家视图 | 玩家认知投影 | 前端面板、推演卡过滤；T-inspire |

## 2. 叙事视图的特殊规则

**读者就是玩家。** 正文会被玩家读到，所以叙事视图里不能出现玩家无权知道、且本场景没有批准揭示的秘密。

叙述者的预示只能使用玩家已知的事实。frontend-example 里的"她还不知道，这场雨会下整整三十天"是合规的，因为三十天暴雨正是玩家自己注入的 IF。

叙事视角（已确认）：默认用第三人称有限视角，每个场景一个视角人物（即 Scene Plan 的 pov）。

## 3. 编译步骤

1. **选焦点**：场景的焦点主体，或任务指定的主体。
2. **扩展相关子图**：焦点的一跳关系，涉及焦点的活跃故事线和趋势，作用范围覆盖焦点的规则。
3. **激活设定条目**：见 §5。
4. **补充历史**：最近 N 个节拍用原文【初始值 N = 6】，更早的用场景摘要。场景摘要在回收阶段生成，只是缓存，不属于 Canon。
5. **可见性过滤**：按视图类型剔除无权看到的事实、信念和条目。叙事视图与检查视图还要按 `ScenePlan.present`（在场主体）过滤：不在场的角色不能把感知到的信息写进正文，在场角色的认知边界就是 `q.beat.knowledge_leak` 的检查范围。
6. **预算裁剪**：按优先级裁剪（规则 > 焦点状态 > 故事线 > 设定条目 > 历史）。
7. **确定性序列化**：键的顺序固定。

## 4. 稳定前缀与 prompt cache

LLM 请求中的内容按稳定程度排列，越稳定的越靠前，这样 provider 的前缀缓存才能生效（Onemore 已经实现了稳定前缀和 cache key）：

1. 任务说明（按任务类型固定）
2. 世界总则与规则
3. 角色设定
4. 常驻的设定条目
5. 文风
6. 动态内容：当前状态切片、场景、候选、历史

## 5. 世界书：设定条目的激活

设定条目（[02 §9](02-世界模型.md)）的激活机制沿用酒馆世界书，这样社区的世界书可以直接导入（字段映射见 [13](13-酒馆兼容.md)）。

| 机制 | IF 中的做法 |
|---|---|
| 常驻 | `constant` 条目始终进入对应的视图 |
| 结构化激活 | 主体处于焦点时，关联它的条目直接激活（IF 新增，比关键词更可靠） |
| 关键词扫描 | 扫描范围：场景计划、最近 N 个节拍、当前任务的输入 |
| 次要关键词 | 沿用 AND ANY / AND ALL / NOT ANY / NOT ALL 四种逻辑 |
| 递归 | 已激活条目的内容可以触发其他条目；递归深度有上限【初始值 2】 |
| 排序与预算 | 按 order 排序；超出预算时从优先级最低的开始丢弃 |
| 概率激活 | 用命运骰子（键为 `lore:<条目 ID>@<场景序号>`），保证可以重放 |
| 定时效果 | sticky、cooldown、delay 按场景数计 |
| 条件激活 | IF 新增：`when` 条件引用事实，例如"好感度 ≥ 50 时激活"（对应变量卡里的条件化条目） |

IF 额外增加的约束：

- **可见性**：secret 条目只进入上帝视图、导演视图，以及 known_by 包含视角人物的角色视图。叙事视图只放 public 条目，以及 reveal_allowed 覆盖到的条目。
- **随世界线变化**：IF 或回溯让某个条目过时时，追加 `lore_superseded`。冲突检测（`q.if.compatible_with`）也覆盖已激活的相关条目。
- **给 Jev 的视图**只放与问题直接相关的条目摘录，因为 Jev 的 state 预算比 LLM 小得多。
