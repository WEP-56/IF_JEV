# 06 裁决策略

Jev 只输出分布，引擎按策略裁决。用哪种策略，由问题的语义类别决定（P7）。

## 1. 问题语义类别

| 类别 | 代号 | 问的是 | 原语 | 策略 | 例子 |
|---|---|---|---|---|---|
| 约束类 | C | 是否违反、是否符合、是否忠实 | Noul / Choice | 阈值；Choice 取概率最大的一项，且该项概率须达到阈值 | 正文是否与锁定事实矛盾 |
| 发生类 | O | 会不会发生、能否成功、是否察觉 | Noul | 带种子抽样 | 顾言是否察觉林夏的异常 |
| 互斥类 | A | 几种互斥的结果中哪一个发生 | Choice | 带种子的分类抽样 | 林夏的反应：回避 / 保护 / 两者皆有 / 没有明显变化 |
| 强度类 | M | 多强、多远、多大 | Score（或 Noul） | 作为数值输入，不抽样 | 本回合对趋势的推动强度 |
| 比较类 | D | 哪个更值得写 | Noul / Score | 作为导演评分中的一项 | 场景的张力变化 |
| 校验类 | V | 已展示的内容应当如何解释 | Noul / Choice | 阈值；失败时只重做抽取，不否决内容 | 抽取结果是否忠实于原文 |

策略在代码里就是 `ResolutionPolicy`，取值与上表一一对应：
`threshold`（C / V）、`seeded_sample`（O）、`seeded_categorical`（A）、
`numeric`（M）、`weighted_select`（D）。

**阈值的方向随模板而变，必须显式声明。** `q.cand.in_character` 是概率越高越可靠，
`q.beat.violates_fact` 是概率越高越可疑，而 `q.if.compatible_with` 又是「概率**低**才判冲突」。
方向写错不会报错，只会静默放过违规正文，所以方向和阈值一样属于表的一部分。

两条硬规则：

- 发生类问题必须用 Noul 的 true/false 定义写成"会发生 / 不会发生"，不能用"是否合理""是否符合人物"来代替。
- 约束类问题的概率永远不拿去掷骰。

## 2. 阈值

阈值按问题模板分别设定，保存在问题库里（见 [07](07-Jev问题库.md)），并随模型版本重新校准。

| 问题 | 规则 | 【初始值】 |
|---|---|---|
| `q.input.is_directive` | p ≥ τ 判为指令 | 0.5 |
| `q.if.parse_faithful` | p ≥ τ 通过 | 0.75 |
| `q.if.compatible_with` | p < τ 判为冲突 | 0.4 |
| `q.if.reconcile_plausible` | p ≥ τ 采用 | 0.6 |
| `q.cand.in_character` | p ≥ τ 保留 | 0.35 |
| `q.cand.knowledge_gap` | p ≥ τ 判为越界 | 0.4 |
| `q.scene.resolves_thread`（受保护的线） | p ≥ τ 否决 | 0.4 |
| `q.beat.violates_fact` | p ≥ τ 判为违反 | 0.3 |
| `q.beat.violates_rule` | p ≥ τ 判为违反 | 0.35 |
| `q.beat.knowledge_leak` | p ≥ τ 判为泄露 | 0.35 |
| `q.beat.forbidden_resolution` | p ≥ τ 判为违反 | 0.3 |
| `q.beat.reveals_secret` | p ≥ τ 判为泄密 | 0.3 |
| `q.beat.stop_reached` | p ≥ τ 结束场景 | 0.6 |
| `q.extract.faithful` | p ≥ τ 保留 | 0.6 |
| `q.extract.missing` | p ≥ τ 要求补抽一次 | 0.5 |
| `q.key.equivalent` | p ≥ τ 合并为同一命题 | 0.8 |
| `q.observe.leaks_secret` | p ≥ τ 重写 | 0.3 |
| L1 保护期内的改变 | p ≥ τ 才允许 | 0.85 |

上表最后一行不是 Jev 问题，而是引擎侧规则（所以没有 `q.` 前缀，代码里的模板 ID 是
`l1_protected_change`）：保护期内的改动用阈值裁决，并且还要求候选有明确的触发事件——
两个条件缺一即否决，且**不转化为趋势**（趋势是「概率落进观察带」的产物，不是「缺少依据」
的产物）。

全局的"一致性严格度"设置按比例线性收紧或放宽所有约束类阈值，并夹在各模板的上下限之间（已确认）。
方向是：越严格，违规类阈值越低（越容易判为违反）、通过类阈值越高（越难通过）。
各模板的真实上下限要等校准才能定，现在统一用 ±40% 作为临时界限【初始值】。

## 3. 抽样

- 发生类：`u < p` 即发生，u 来自命运骰子（见 [03 §8](03-事件与世界线.md)）。
- 互斥类：选项按选项 ID 排序后累加分布，看 u 落在哪个选项上。
- 抽样结果连同 p、u、决策键一起写入回合记录。

## 4. 分层抽样

同一请求中的问题是独立评估的。如果每个候选各自独立掷骰，可能掷出不自洽的组合，例如"保护 ✗、回避 ✗、察觉异常 ✓"。因此按依赖分层裁决：

```
layers = 按 depends_on 对候选做拓扑排序
temp   = 当前的预演状态
for layer in layers（最多"因果深度"层，【初始值 3】）:
    问 Jev：本层每个发生类候选的 p（行为用角色视图，世界事件用上帝视图），
            以及每个互斥组的分布
    用命运骰子裁决
    通过的写入 temp
    被否决、但 p ≥ τ_watch 的转为趋势（§5）
    下一层在更新后的 temp 上重新判定
```

- 依赖关系由 LLM 在 `propose_candidate` 中标注，引擎检查不存在环。
- 下游候选一律在更新后的临时状态上重新判定，不需要区分"必要条件"和"影响因素"：前提不成立时，Jev 自然会给出很低的概率。
- 互斥组只用一个 Choice 抽一次，组内的候选不再单独掷骰。
- 超出层数上限的下游候选，留到下一回合或转为趋势。
- 【可选】最后用 `q.cand.coherent` 检查整组结果。判为矛盾时，丢弃最后一层的结果并重新判定一次。

L1 保护期内：改变受保护状态的候选不参与抽样，改用阈值（p ≥ 0.85），并且必须有明确的触发事件。

## 5. 观察带与趋势

| 参数 | 【初始值】 | 说明 |
|---|---|---|
| τ_watch | 0.3 | 发生类候选被否决、但 p ≥ τ_watch 时，转为趋势 |
| 初始压力 | p × 0.5 | |
| 推动量 | 削弱 −0.1 / 无影响 0 / 轻微 +0.05 / 明显 +0.15 / 强烈 +0.3 | 每回合对活跃趋势问 `q.tendency.push` |
| 衰减 | 每个场景 × 0.95 | |
| 爆发阈值 | 0.8 | 达到后进入下一回合的候选池，作为高优先级的发生类候选，并在导演评分中获得加成 |
| 消散 | 低于 0.05 | 状态改为 dissolved |

## 6. 导演评分

每一项先归一化到 [0, 1]，再加权求和：

```
score = Σ wᵢ · termᵢ
```

| 项 | 来源 | 计算 |
|---|---|---|
| semantic_fit | Jev `q.scene.fit` | p |
| tension_gain | Jev `q.scene.tension` | `score / (等级数 − 1)`，归一化到 [0, 1]（见 §7） |
| thread_pressure | 引擎 | 该场景推进的故事线的平均压力 |
| overdue_bonus | 引擎 | `clamp(距上次推进的场景数 / cadence − 1, 0, 1)` |
| character_balance | 引擎 | 焦点角色的出场缺额 |
| tendency_bonus | 引擎 | 该场景是否让高压趋势爆发 |
| repetition_penalty | Jev `q.scene.repetitive` | −p |
| premature_resolution | Jev `q.scene.resolves_thread` | 受保护的线：直接否决（第 8 步已经过滤）；未受保护但接近解决的：−p |

选择方式：`P(i) ∝ exp(score_i / T)`，T 为叙事温度【初始值 0.15】，用键为 `scene_select@<叙述序号>` 的命运骰子抽取。这样既不是完全随机，也不会永远只取最高分。

**导演风格就是一组权重，由模板定义。** 下表的数值仅作示意【初始值】：

| 风格 | fit | tension | thread | overdue | balance | tendency | repetition |
|---|---|---|---|---|---|---|---|
| 均衡（默认） | 1.0 | 0.8 | 0.6 | 0.5 | 0.4 | 0.6 | 0.8 |
| 慢热言情 | 1.0 | 0.4 | 0.8 | 0.3 | 0.6 | 0.8 | 0.6 |
| 悬疑 | 1.0 | 0.9 | 0.7 | 0.6 | 0.3 | 0.9 | 0.9 |
| 爽文 | 0.8 | 1.0 | 0.5 | 0.8 | 0.2 | 0.5 | 0.7 |

## 7. 强度映射

**Jev 的 Score 原语返回的是 0 基连续分数**（实测：5 个等级时区间为 0–4，如 `score = 3.73`），同时给出 `legend`（索引 → 标签）和各级概率。因此映射不能在引擎里写死成"第几级 = 哪个数"，而要按等级数归一化：

```
value = score / (等级数 − 1)        # 等级数 = criteria 数组长度；上限 10
```

| 问题 | 归一化后的数值含义 |
|---|---|
| `q.scene.tension` | 0 = 明显缓和，0.25 = 略微缓和，0.5 = 持平，0.75 = 略微升高，1 = 明显升高 |
| `q.claim.credibility` | 不按归一化取值，按等级直接映射：完全不信 0.1 / 存疑 0.3 / 半信半疑 0.5 / 基本相信 0.75 / 深信不疑 0.95。用 `legend` 对齐标签后取值 |
| `q.tendency.push` | 见 §5 |
| `q.cand.relevance` | 无关 0 / 间接 0.33 / 明显 0.67 / 直接 1；评为"无关"的候选直接丢弃。同上，用 `legend` 对齐 |

`legend` 是索引到标签的映射，引擎应当据它把分数换算成语义值，而不是假定等级数恒为 5。

## 8. 机制的随机取值

对于带范围的机制（例如江水位每天上涨 0.4–1.2 m）：`value = min + u × (max − min)`，u 来自键为 `<机制 ID>@<机制步>` 的命运骰子。

## 9. 失败与降级

- Jev 请求失败：重试 2 次，指数退避【初始值】。仍然失败时暂停回合并提示用户；用户可以手动切换到 LLM 裁判后端（判定记录上注明所用的后端）。
- 判定结果缺失或格式异常：约束类视为"不通过"，发生类视为"不发生"，并记录下来。
