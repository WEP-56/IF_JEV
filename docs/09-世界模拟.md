# 09 世界模拟

## 1. 三级分辨率

| 层级 | 范围 | 模拟方式 |
|---|---|---|
| 前景 Foreground | 当前场景 | 逐个行动、逐条认知 |
| 活跃后台 Active | 与当前故事线直接相关 | 按场景或时间段批量结算 |
| 休眠 Dormant | 暂时无关 | 只运行机制规则和趋势，不模拟个体的行动 |

### 1.1 升降级

- **升为前景**：出现在当前场景中。
- **升为活跃后台**：满足任一条件：关联着活跃的故事线；最近 5 个场景【初始值】中被提及；目标与前景角色有交集；被用户的 IF 直接指向。
- **降级**：连续 10 个场景【初始值】都不满足上述条件。升级和降级的条件之间留有滞后区间，避免来回抖动。

## 2. 时间推进

- 每个场景的世界时间跨度由场景计划决定（来自 Jev 和导演选择，不由用户决定）。
- 场景结束时，按经过的时间逐步执行机制：每个机制步执行一次，用命运骰子取值，并检查触发器。
- 机制步长是一项世界设置（对应前端现在的"时间粒度"），例如"天"。

## 3. 后台结算

触发时机：场景结束、且经过的世界时间不少于一个机制步；或者镜头即将切到某个后台主体。

1. 任务 T-offscreen 根据上次的状态、经过的时间、主体的目标、世界事件和活跃趋势，提出"这段时间里发生了什么"的候选。
2. 引擎对每个候选问 `q.bg.occurs`（上帝视图），用命运骰子裁决。
3. 通过的候选写入 `background_settled`。这些事件不展示，默认对玩家隐藏，以后可能作为暗线浮现。

后台事件不经过展示边界，所以在结算时直接提交。

## 4. 休眠世界

- 只保留宏观状态（例如民心、粮食储备）和潜在趋势。
- 机制规则照常运行（例如"民心每天下降 x"），触发器照常检查（例如"民心 < 40 时触发抢购事件链"），触发结果进入候选池或成为趋势。
- 用户的 IF 指向休眠区域时：写入事实，并为该区域生成一个高压趋势，由导演决定它何时浮现。
