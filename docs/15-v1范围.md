# 15 v1 范围

> 本文固定第一版做什么、不做什么。与其他文档中的【v1】/【后续】标注冲突时，以本文为准。

## 1. 取舍原则

1. **00 §7 的五项不可推迟项全部进入 v1**：最小承诺、Reality / Belief / Claim 分层、正文回收、事件日志作为存储结构、问题库版本化加标注集。
2. **凡是会写入事件日志格式的东西，v1 定好 schema**；功能本身可以后做。这样后续功能不需要迁移旧世界文件。
3. **需要"世界线重算"的功能推迟**（00 §7 第 4 条已允许）。只移动头指针、只追加事件的功能保留。
4. **纯性能优化推迟**，先保证回合流程正确，再按实测延迟决定优化顺序。
5. **只有沙盒模式**。挑战模式相关的一切只预留接口。

## 2. v1 必做

### 2.1 用户动作与 IF

| 项目 | 说明 | 依据 |
|---|---|---|
| 三种动作 | IF、观测、继续 | 01 §2、04 §1 |
| 导演指令检测与改写 | `q.input.is_directive` + T-rewrite | 01 §4 |
| IF 类型 | 状态型、认知型、规则型、事件型、真相型 | 01 §5 |
| 回溯型 IF | **只支持"重释"策略**（只追加补充事实，不需要重算下游） | 01 §12、03 §7 |
| 裁定卡 | 全部字段；自动确认默认关闭（D3） | 01 §9 |
| 锁定与冲突 | L0–L3、L1 保护期 3 个场景（D2）、用户 IF 冲突先重释后覆盖（D4） | 01 §7、§10 |
| 规则编译 | 不变量、机制、触发器、语义约束 | 01 §11 |
| 观测 | 每个场景边界 1 次（D6） | 01 §13 |
| 世界线偏移 | 只展示与累计 | 01 §15 |
| 模式 | 仅沙盒 | 01 §16 |

### 2.2 回合与裁决

- IF 回合第 1–14 步、继续回合、观测全部实现（04 §2–§5）。
- 分层裁决、命运骰子（BLAKE3）、互斥组、观察带与趋势、导演评分（06）。
- 节拍放行：逐节拍送检、重试与兜底、每场景节拍上限、背压、停止（04 §4、§6）。
- Proposed / Observed / Committed 对账（P4）。
- 故事线的阶段推进（只允许相邻阶段，D8），受保护线的 forbidden_resolutions。
- 在场集合只记录场景级（02 已确认）。
- 第 14 步只做后台结算和 T-inspire（IF 灵感）；命运节点提示推迟。

### 2.3 世界模拟

- 前景 + 活跃后台 + 休眠三级，升降级按 09 §1.1 的初始值。
- 机制步进、触发器、T-offscreen 后台结算、休眠区域的高压趋势（09 §2–§4）。

### 2.4 世界线操作

分支、回到此处、回滚、重写（swipe，沿用骰子）、重掷（换盐值）全部进入 v1——它们只创建或移动头指针。

未选之路：v1 **记录**导演未选中的场景候选并在 IF 导图中显示（折叠）；"走这条路"需要在该点重新生成，一并进入 v1，复用分支 + 指定场景候选的路径。

### 2.5 视图与世界书

- 上帝、导演、角色、叙事、检查、解析、玩家视图（08）；角色视图中不得出现秘密，有快照测试保证。
- 世界书激活与预算裁剪；确定性序列化。
- 叙事视角默认第三人称有限（D12）。
- 调试用全知视图开关。

### 2.6 世界创建与导入

| 入口 | v1 | 说明 |
|---|---|---|
| 一句话起世界 | ✓ | 最短的上手路径，优先实现 |
| 引导创建 | ✓ | 9 步都可跳过；先保证能走完，不追求每一步体验 |
| 模板 | ✓ | 内置 1 个示例世界（由"雨城纪事"改写，去掉 11 §7 列出的违规内容） |
| 导入 | ✓ | 见 §2.7 |

- 世界草案检查（10 §3）、世界卡、封存秘密（D13）、每个世界独立的世界设置（10 §5）。
- 定型：只做"核心设定升为 L2"与"界面编辑走状态型 IF"；立绘生成推迟。

### 2.7 酒馆兼容

- 角色卡 V2 / V3，PNG 与 JSON；世界书 JSON；世界书激活机制（13 §1 标为【v1】的三项）。
- `{{user}}` 转为由世界推演的主角（D14）。
- 单卡导入。群聊卡推迟。
- 实现前必须先完成 13 §6 待核实清单的 1–3 项，并收集导入测试集（至少 10 张卡）。

### 2.8 Agent 与后端

- if-agent：Onemore 移植 + OpenAI Chat Completions 适配器 + 数组 schema 校验 + `JudgeRejected`（05）。
- 结构模型 / 叙事模型两个槽位。
- Judge 后端：Jev、LLM 裁判、测试桩三个都做（LLM 裁判是 D11 的降级路径，不能缺）。
- 问题库带版本号；关键约束类问题有人工标注集，并有回归入口（07 §6）。

### 2.9 前端

- 输入区三种动作、裁定卡、推演卡（按玩家视图过滤、可观察结果显示骰子，D15）、按节拍展示。
- 叙事消息操作：复制、重写、重掷、从此处分支。
- 右侧面板：角色（认知来源标注）、世界（机制、暗流）、IF 导图（含 swipe / 未选之路，折叠）。
- 设置：按 11 §6，**去掉生图和 WebDAV**。

### 2.10 工程

- crate 划分按 12 §2。
- Tauri 命令与事件按 12 §4；**v1 同一时间只打开一个世界**（仍然使用独立的世界工作线程，便于以后放开）。
- 每个世界一个 SQLite 文件；密钥进系统钥匙串；导入卡中的脚本不执行；CSP。
- 测试：回合流程、重放、视图快照、工具 schema（12 §8）。
- 可观测性：判定记录、阶段耗时、token 用量、回合记录导出。

## 4. v1 完成标准

1. 用一句话起世界、导入一张酒馆卡、使用内置模板，三条路径都能进入第一个场景。
2. 在同一个世界里连续跑 20 个回合（IF、继续、观测混合），期间做一次分支、一次重掷、一次回滚、一次回溯型 IF（重释），无崩溃、无未提交的已展示节拍。
3. 重放测试：任意世界文件重放事件日志得到的投影与存储的投影一致。
4. 视图快照测试覆盖所有视图种类，角色视图与叙事视图中不出现越权信息。
5. Jev 不可用时能暂停并切换到 LLM 裁判继续。
6. 关键约束类问题的标注集回归通过，阈值已按标注集校准（TODO"固定问题模板版本与阈值"）。
7. 用户完成真实 Jev / LLM 的端到端演练和叙事质量验收（按 AGENTS.md，由用户执行）。
