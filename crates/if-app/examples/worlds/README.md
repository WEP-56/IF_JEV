# 作者世界包（`.world.json`）

一份**手写的世界**，落成一个完整的 `.ifworld`。

## 为什么需要它

IF 的着力点是**命题**：`IF 上游水库的出库数据一直被人为篡改` 之所以能起作用，
是因为世界里有一条叫「出库数据是否被篡改」的命题可以被改写；没有命题，这条 IF 无处落脚。

而**导入**（酒馆卡 / 世界书）产不出命题。`if-app::seed` 只做**确定性映射**——角色变主体、
条目变设定——因为从一段散文里猜「这句话是一条命题」属于语义判断，猜错等于静默改写世界前提
（P13，见 `docs/02 §9.1` 的分流）。于是刚导入的世界是「主体 1 / 命题 0」，跑回合时每个候选
都拿不到稳定决策键，引擎只能退回候选 ID 兜底（`docs/03 §8`）——这正是 2026-09-27 真机上
「T-impact 没有产出任何提议」的根子（`docs/16 §3`）。

作者世界补上这一半：每一条命题、事实、规则都是作者**明说**的，没有猜的余地。
所以 `seed` 少做是因为**不能猜**，这里做全是因为**不用猜**。

## 怎么用

```bash
# 看一份包里有什么（只校验，不写文件）
cargo run -p if-app --example build_world -- --check examples/worlds/linjiang.world.json

# 落成一个可以打开的 .ifworld（不给输出路径就写在输入旁边）
cargo run -p if-app --example build_world -- examples/worlds/linjiang.world.json
```

不联网、不花额度。写出来的世界和「应用里建会话」走的是同一条代码路径
（事件 ID 先算号再写），所以两边的投影没有区别。

> **还没接进应用。** 会话创建（`create_session`）目前只认导入结果（`ImportedWorld`）；
> 把作者世界接进去是下一步（`docs/16 §5`）。在那之前，这个入口是唯一能落作者世界的地方。

## 两个世界

| 文件 | 用途 | 规模 |
|---|---|---|
| `examples/worlds/linjiang.world.json` | **示例**：临江市，一份按 `docs/01` 的六种 IF 类型写全的世界 | 主体 5 · 命题 8 · 事实 8 · 规则 3 · 设定 7 · 故事线 3 |
| `tests/fixtures/worlds/ferry.world.json` | **测试夹具**：渡口，小到能在一屏里读完，供回合链路测试用 | 主体 2 · 命题 3 · 事实 3 · 规则 1 · 设定 2 · 故事线 1 |

### 临江市

依据 `docs/01` 与 `docs/11 §7` 里那份修正过的设定写的：长江中游的一座城市，梅雨季第一天夜里
开始下雨。它刻意覆盖了六种 IF 各自的着力点——

| IF 类型 | 可以这样试 | 命中的命题 |
|---|---|---|
| 状态型 | `IF 沈知遥已经开始怀疑周望川` | `c_shen.trust.c_zhou` |
| 认知型 | `IF 周望川早就知道数据被篡改` | `c_zhou.knows_tampering` |
| 规则型 | `IF 本季的暴雨会持续三十天` | `world.rain_days` · `c_reservoir.level`（规则带机制与触发器） |
| 事件型 | `IF 青石水库的调度记录昨夜被人删了` | `c_reservoir.data_tampered` |
| 真相型 | `IF 上游水库的出库数据一直被人为篡改` | `c_reservoir.data_tampered`（`secret`，只有周望川知道） |
| 回溯型 | `IF 那座水库其实从来没有建成过` | 与已展示内容冲突，走裁定卡 |

> 名字与前端侧栏里那条**演示故事**「雨城纪事」同源，但不是一回事：演示故事背后没有世界文件，
> 发 IF 落不到它身上。把两者在界面上分开是另一件事（`docs/16 §4`）。

### 渡口

`git` 里第二份作者世界，只为了让回合链路有一个**确定性**的输入：两个角色、三条命题、
一条带触发器的规则、一条受保护的故事线。`crates/if-app/src/authored/tests.rs` 用它跑
「建世界 → 确认裁定卡 → 五个任务 → 写事件」的完整回合，并且**成对**地验证：

- 有命题 → 候选落在真实命题上，决策键稳定；
- 抽走命题 → 同一份剧本立刻退化，引擎如实报出「没有稳定决策键」。

## 格式

顶层字段与 `if-domain` 的领域类型一一对应，只有一处刻意的不同：**凡是「由哪个事件引入」
的字段（`created_by` / `source`）都不在文件里**——它们要到写入那一刻才知道，由加载器回填。
写进 JSON 只会逼作者填一个假值。

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | ✓ | 世界名。文件名与 ID 从它来 |
| `genre` / `summary` | | 题材与一句话简介 |
| `settings` | | 世界设置。给了它，**命运骰子种子就是钉死的**——同一份包永远掷同一串骰子。不给则种子取 0 |
| `subjects` | | 主体。`id` / `kind` / `name` 必填；`tier` 默认 `active`，`shaped` 默认 `false` |
| `propositions` | | 命题。**这是 IF 的着力点**，字段与 `Proposition` 相同（`id` / `key` / `text` / `subjects` / `kind` / `value_type` / `internal`） |
| `facts` | | 事实。`prop` 写命题 **ID**；`value` 可以直接写标量（`true` / `22.1` / `"晴"`）；`visibility` **必填** |
| `rules` | | 世界规则。`lock` 默认 **L2**（`docs/01 §6` 的规则型默认）；`active_from_days` 用天数写 |
| `lore` | | 设定条目。`section` 默认 `world`，`visibility` 默认 `public`；`status` 不收——新世界里没有「已被取代」的条目 |
| `threads` | | 故事线。`pressure` / `cadence` / `last_advanced` 有默认值，作者只写「在问什么、什么阶段、保护到哪」 |

引用一律写 **ID**（`p_` / `c_` / `thr_`…）——包括 `facts[].prop`、规则条件里的 `prop`、
设定条目的 `subjects` 与 `known_by`。**规范键（`key`）只用来给模型看，不用来互相引用**：
键是给人读的（`c_reservoir.level`），ID 是给机器认的（`p_river_level`），两件事分开，
改名时就不会牵动一整张引用网。

写入顺序固定：**主体 → 命题 → 事实 → 规则 → 设定 → 故事线**。所以事件 ID 永远可复现。

### 会当场报错的三类写法

加载器**先校验再映射**，一次报出全部问题，并且指得出是哪一类对象的哪一条：

1. **悬空引用**——事实挂了不存在的命题、规则的作用域指向不存在的主体、条件里的命题 ID 不存在；
2. **ID 或规范键重复**——规范键是决策键的一部分，撞键会让两条不同的命题共用同一颗骰子；
3. **字段名打错**——顶层与各类条目的结构都开了 `deny_unknown_fields`。把 `propositions`
   打成 `propostions`，你得到的是「你打错了」，而不是一个「不知道为什么没有命题」的世界。

引擎侧还有一道保险（`append_batch` 折叠投影时会拒绝悬空引用），但那道报错说不出文件里的位置，
所以校验放在加载器里。
